# 启动训练

当前方案（数据集 `armpi_train_v1`，1×RTX3090）的训练启动命令。

---

## 一、启动

```bash
cd /home/zyy00005602/MyWork/Lerobot/remote_SmolVLA

LEROBOT_BATCH_SIZE=64 \
LEROBOT_NUM_WORKERS=6 \
LEROBOT_SAVE_FREQ=2000 \
nohup ./scripts/train_armpi.sh armpi_train_v1 20000 \
  > train_armpi_v1.log 2>&1 &

tail -f train_armpi_v1.log
```

必须用 `nohup ... &`。训练要跑 3 小时以上，JupyterLab 页面一断，前台进程就没了。

## 二、这条命令在做什么

```bash
./scripts/train_armpi.sh <数据集目录名> <训练步数>
```

| 片段 | 含义 |
|---|---|
| `armpi_train_v1` | 数据集目录名。脚本拼成 `/home/zyy00005602/MyWork/Lerobot/dataset/armpi_train_v1` |
| `20000` | 训练步数（优化器步数，不是 epoch） |
| `LEROBOT_BATCH_SIZE=64` | 实测 1 相机峰值 8.72 GiB，吞吐 110 样本/s。batch 从 64 起吞吐已压满 |
| `LEROBOT_NUM_WORKERS=6` | 视频解码进程数。容器限 12 核，4~6 合适 |
| `LEROBOT_SAVE_FREQ=2000` | 每 2000 步存一个 checkpoint。61 集容易过拟合，多存几个用于挑 |

脚本内部还会自动做三件事（不用你管）：

1. 调用 `lerobot-train-bf16` 包装器（不能用 `lerobot-train`，0.6.1 的精度推断会崩）
2. 导出 `HF_ENDPOINT=hf-mirror.com` 等环境变量（非登录 shell 读不到 `.bashrc`）
3. 自动补 `--rename_map`，把数据集的 `observation.images.front` 映射成 `camera1`

## 三、预计耗时

61 集 6662 帧，batch 64 时每 epoch 约 104 步：

| steps | 大致耗时 | 说明 |
|---|---|---|
| 10000 | ~1.7 h | 想先看效果 |
| **20000** | **~3.3 h** | **推荐** |
| 30000 | ~5 h | 数据更多才值得 |

## 四、怎么盯

每 50 步打一行（`LEROBOT_LOG_FREQ` 可调）：

```
step:50 smpl:3200 ep:... epch:... loss:1.0xx grdn:... lr:...
       updt_s:0.6 data_s:0.0 smp/s:1xx mem_gb:9.xx
```

| 字段 | 期望 | 异常时 |
|---|---|---|
| `loss` | 先快降、后缓降 | 掉到 0.0x 还在降 = 过拟合，回头看中间的 checkpoint |
| `mem_gb` | ~10 GiB | 接近 20 就该降 batch |
| `data_s` | ≈ 0 | 接近或超过 `updt_s` = 数据加载跟不上，调大 `LEROBOT_NUM_WORKERS` |

启动横幅长这样，先确认数据集和相机映射对不对：

```
==============================================================
 数据集   : /home/zyy00005602/MyWork/Lerobot/dataset/armpi_train_v1
            版本=v3.0  机器人=armpi  episodes=61  frames=6662  fps=25
 相机     : observation.images.front
            映射={"observation.images.front":"observation.images.camera1"}
            自动生成 ⚠ 部署侧必须用同一套映射
 输出     : .../outputs/armpi_train_v1_smolvla_0918_2231
 训练     : steps=20000  batch=64  workers=6
 base 权重: lerobot/smolvla_base（从 hf-mirror 拉取）
==============================================================
```

## 五、产物

```
remote_SmolVLA/outputs/armpi_train_v1_smolvla_<月日>_<时分>/
└── checkpoints/
    ├── 002000/ 004000/ ...            # 每 save_freq 步一个
    │   └── pretrained_model/          # ← 部署要的就是这个目录
    └── last -> 002000/
```

⚠️ **不要直接拿 `last` 上线。** 61 集数据量偏小，最优 checkpoint 经常在中途。
把 `002000 / 004000 / … /last` 都拷到 ArmPi Ultra 真机跑一遍，挑成功率最高的那个。

## 六、续训

崩了要用**同一个运行名**续，让输出目录指回原目录：

```bash
cd /home/zyy00005602/MyWork/Lerobot/remote_SmolVLA

LEROBOT_RUN_NAME=armpi_train_v1_smolvla_0918_2231 \
LEROBOT_BATCH_SIZE=64 LEROBOT_NUM_WORKERS=6 LEROBOT_SAVE_FREQ=2000 \
nohup ./scripts/train_armpi.sh armpi_train_v1 20000 --resume=true \
  >> train_armpi_v1.log 2>&1 &
```

运行名就是第五节输出目录的最后一段。**不要再手动传 `--output_dir`**，脚本里已经设了，重复传会参数冲突。

## 七、停

```bash
# 找进程
pgrep -af "lerobot-train-bf16|train_armpi"

# 优雅停止（会存下当前 checkpoint）
kill -INT <pid>

# 确认显存释放
nvidia-smi
```

## 八、预热（可选）

正式跑之前想确认这台机器一切正常，两条只读检查：

```bash
source /opt/conda/etc/profile.d/conda.sh
conda activate /home/zyy00005602/.conda/envs/lerobot
cd /home/zyy00005602/MyWork/Lerobot/remote_SmolVLA

python scripts/verify_env.py --quick                                     # 依赖/GPU 自检
python scripts/check_dataset.py ~/MyWork/Lerobot/dataset/armpi_train_v1 --decode  # 数据集校验
```

`--decode` 会真的解几帧视频，是训练跑起来之前唯一能发现视频损坏的机会。
